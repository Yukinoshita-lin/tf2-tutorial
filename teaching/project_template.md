# 从零搭建你的第一个深度学习项目

> 写给第一次做自己的深度学习项目的同学
> 跟着这 7 步走，把教程上学到的知识迁移到你自己的数据集上

---

## 前言：为什么要做自己的项目？

跟着教程做项目和自己从零做项目，完全是两回事。

教程里的数据都是清洗好的、代码都是能跑通的、结果都是预期的。但真实世界不是这样——数据可能乱七八糟、模型可能就是不收敛、效果可能差得离谱。

**自己踩过的坑，才是真正学到的东西。**

这份指南会带你走完一个完整的深度学习项目流程，每一步都会告诉你"要做什么"、"为什么要这么做"，以及"常见的坑有哪些"。

---

## 第一步：选一个数据集

第一次做自己的项目，**数据集的选择比模型还重要**。选对了数据集，事半功倍；选错了，可能折腾一周还在数据坑里打转。

### 给初学者的 5 个推荐数据集

| 数据集 | 任务类型 | 类别数 | 数据量 | 难度 | 说明 |
|--------|---------|--------|--------|------|------|
| **Fashion-MNIST** | 图像分类 | 10 类（衣服/鞋子/包等） | 6 万张 28×28 灰度图 | ★☆☆ | MNIST 的时尚版，比手写数字有意思，数据干净 |
| **Cats vs Dogs** | 图像分类 | 2 类（猫/狗） | 2.5 万张彩色图 | ★★☆ | 经典二分类任务，数据好找，趣味性强 |
| **Rock-Paper-Scissors** | 图像分类 | 3 类（石头/剪刀/布） | 约 3000 张手势图 | ★★☆ | 手势识别，数据量小，甚至可以自己拍照片扩充 |
| **Brain MRI（脑部 MRI）** | 医学图像分类 | 2 类（有肿瘤/无肿瘤） | 约 5000 张 MRI 切片 | ★★★ | 医学图像方向，数据稍复杂，适合想做医疗 AI 的同学 |
| **Caltech 101（子集）** | 图像分类 | 选 5-10 类 | 每类几十到几百张 | ★★★ | 经典数据集，类别多，可以挑自己感兴趣的类别做 |

### 选数据集的三个原则（第一次做项目务必遵守）

1. **数据量不要太大**：第一次做项目，几百到几千张图就够了。数据太大 = 训练太慢 = 调试效率低 = 容易放弃。
2. **类别不要太多**：3-10 类比较合适。类别越多，问题越复杂，需要的数据量和模型容量也越大。
3. **数据要"干净"一点**：尽量选已经整理好的数据集。不要一上来就从网上爬乱七八糟的图片——数据清洗会花掉你 80% 的时间。

> 💡 **小建议**：如果你完全没有想法，就从 Fashion-MNIST 开始。它和 MNIST 一样好上手，但比数字识别更有成就感。

## 第二步：项目结构模板

好的目录结构能让你的项目井井有条，也方便别人看懂。推荐下面这个结构：

```
my_project/                    # 项目根目录
├── data/                      # 数据文件夹
│   ├── raw/                   # 原始数据（下载下来什么样就什么样，别动！）
│   ├── train/                 # 训练集
│   │   ├── class_a/           # 每个类别一个子文件夹
│   │   ├── class_b/
│   │   └── ...
│   ├── val/                   # 验证集
│   │   ├── class_a/
│   │   ├── class_b/
│   │   └── ...
│   └── test/                  # 测试集
│       ├── class_a/
│       ├── class_b/
│       └── ...
├── notebooks/                 # Jupyter 笔记本（做实验、画图画）
│   ├── 01_data_exploration.ipynb
│   ├── 02_baseline_model.ipynb
│   └── 03_experiments.ipynb
├── models/                    # 保存训练好的模型
│   ├── best_model.keras
│   ├── best_model_saved/      # SavedModel 格式
│   └── best_model.tflite
├── output/                    # 输出的图表、日志等
│   ├── figures/               # 分析图
│   │   ├── sample_images.png
│   │   ├── history.png
│   │   ├── confusion_matrix.png
│   │   └── wrong_predictions.png
│   └── logs/                  # TensorBoard 日志
├── src/                       # 源代码（可以复用的函数）
│   ├── data_utils.py          # 数据加载、预处理相关
│   ├── model_utils.py         # 模型构建相关
│   └── train_utils.py         # 训练相关
├── reports/                   # 项目报告
│   └── project_report.md
├── requirements.txt           # 依赖包列表
└── README.md                  # 项目说明
```

### 为什么要这么分？

- **data/raw 不动**：原始数据下载下来就别动了，处理过程写在代码里。这样数据坏了可以随时重新生成，也保证了可复现性。
- **notebooks 做实验，src 放代码**：Jupyter 适合探索和画图，但不适合写复杂逻辑。成熟的函数搬到 src 里，notebook 里 import 过来用。
- **output 和 models 分开**：模型是"产品"，图表是"分析结果"，放在一起会很乱。

## 第三步：7 步完成你的项目

### 步骤 1：数据收集与整理

**要做什么**：
- 下载数据集
- 按类别组织成文件夹结构（ImageFolder 格式）
- 划分训练集 / 验证集 / 测试集

**为什么要这么做**：
- 按类别建子文件夹是最通用的数据组织方式，Keras 的 `image_dataset_from_directory` 直接就能用。
- 数据划分一定要在**最开始**做好，而且测试集一旦划分好就**绝对不能碰**——不然就失去了"最终考试"的意义。

**具体操作**：
1. 下载数据，解压到 `data/raw/`
2. 看一下数据的目录结构，了解每类有多少张
3. 写一个脚本（或用 `splitfolders` 库）按比例划分：
   - 训练集：70%~80%
   - 验证集：10%~15%
   - 测试集：10%~15%
4. 划分后检查一下：每类在三个集合里的比例是否一致（分层抽样）

**常见问题**：
- ❌ 忘了 shuffle 就划分 → 某一类全分到测试集了
- ❌ 测试集划得太大 → 训练数据不够
- ❌ 用测试集调模型 → 数据泄露，结果不真实

---

### 步骤 2：数据探索

**要做什么**：
- 统计数据基本信息：总张数、每类张数、图片尺寸
- 看一些样例图片：数据长什么样？质量怎么样？
- 检查类别平衡：各类数量差不多吗？
- 检查数据质量：有没有损坏的图片？有没有标错的？

**为什么要这么做**：
- 你对数据越了解，后面建模型时越有方向。
- 很多时候模型效果不好，根本不是模型的问题，是数据本身有问题——比如某类图片特别少、或者有很多标错的。
- 这一步只花 30 分钟，但可能帮你省下后面好几天的瞎调。

**具体操作**：
1. 用代码统计：总图片数、每类图片数、图片尺寸分布
2. 画一个柱状图：每类有多少张图
3. 每个类别挑几张样例图拼在一起，看看数据长什么样
4. （可选）检查有没有损坏的文件、尺寸特别奇怪的图

**要回答的问题**：
- [ ] 一共有多少张图？多少个类别？
- [ ] 类别平衡吗？最多的类和最少的类差几倍？
- [ ] 图片都是什么尺寸？需要 resize 吗？
- [ ] 数据质量怎么样？有没有明显标错的？

---

### 步骤 3：选模型

**要做什么**：根据你的数据情况，选择合适的模型类型。

**为什么要这么做**：
没有最好的模型，只有最合适的模型。选对了模型，事半功倍；选错了，要么效果差，要么训练慢。

**决策树：怎么选模型？**

```
你的任务是什么？
│
├── 图像分类任务
│   │
│   ├── 数据量很小（每类 < 100 张）？
│   │   └── → 用迁移学习（MobileNetV2 / ResNet50），只训分类头
│   │
│   ├── 数据量中等（每类 100~1000 张）？
│   │   └── → 用迁移学习 + 微调（冻结训分类头 → 解冻顶层微调）
│   │
│   └── 数据量很大（每类 > 1000 张）？
│       └── → 可以用迁移学习，也可以考虑从零训一个 CNN
│
└── 其他任务（文本、语音...）
    └── → 先找对应的预训练模型，思路和迁移学习类似
```

**给初学者的建议**：
- **第一次做项目，直接上迁移学习**。别从零训 CNN——数据不够 + 经验不足，很容易翻车。
- **从 MobileNetV2 开始**。它又小又快，效果也不错，很适合初学者。
- **等 baseline 跑通了，再考虑换模型**。不要一开始就纠结"用 ResNet 还是 EfficientNet"。

---

### 步骤 4：训练 baseline（基线模型）

**要做什么**：先跑一个简单的模型，建立 baseline，看看"不加任何技巧时效果如何"。

**为什么要这么做**：
- 很多同学一上来就堆各种高级技巧——复杂的模型、花式数据增强、各种调参……结果代码写了一大堆，跑起来全是 bug。
- 正确的做法是：**先跑通，再优化**。先有一个最简单的 baseline，知道"基准线"在哪，后面每做一个改动，才能知道有没有用。
- baseline 就像考试的"摸底测"——知道自己现在多少分，才能评估后续努力的效果。

**具体操作（以迁移学习为例）**：
1. 用 Keras 加载预训练模型（MobileNetV2），冻结所有层
2. 加一个简单的分类头（GlobalAveragePooling2D → Dense → 输出层）
3. 正常学习率（1e-3）训练分类头
4. 训练 5-10 个 epoch，记录验证准确率
5. 保存这个 baseline 模型和训练曲线

**baseline 的标准**：
- 代码能跑通，不报错
- 验证准确率明显高于随机猜测（比如 10 分类随机是 10%，baseline 至少要到 50%+）
- loss 在下降，说明模型在学习

**常见误区**：
- ❌ 一上来就用最复杂的模型 → 出了 bug 都不知道在哪
- ❌ baseline 还没跑通就开始调参 → 方向都没找对，调了白调
- ❌ 只看训练准确率不看验证准确率 → 过拟合了还不知道

---

### 步骤 5：调优

**要做什么**：在 baseline 的基础上，一步步改进，提升模型效果。

**为什么要这么做**：
调参不是瞎试，要有章法。每次只改一个变量，才能知道"是什么导致了效果变化"。

**推荐的调参顺序（从性价比高到低）**：

| 优先级 | 调什么 | 怎么做 | 预期提升 |
|--------|--------|--------|---------|
| ⭐⭐⭐ 最高 | 数据质量 | 清理数据、修正标签、补充困难类的数据 | 可能最大 |
| ⭐⭐⭐ 最高 | 数据增强 | 加入适合数据的增强方式（翻转、旋转、缩放等） | 明显提升 |
| ⭐⭐⭐ 高 | 迁移学习微调 | 解冻顶层，用小学习率微调 | 1%~5% 提升 |
| ⭐⭐ 中 | 学习率 | 试不同的学习率（1e-2 / 1e-3 / 1e-4） | 有影响 |
| ⭐⭐ 中 | 分类头结构 | 加/减隐藏层、改变神经元数量 | 小幅提升 |
| ⭐ 低 | 换更大的模型 | MobileNetV2 → ResNet50 → EfficientNet | 可能提升，但训练更慢 |
| ⭐ 低 | 优化器选择 | SGD → Adam → AdamW | 影响不大 |

**调参的黄金法则**：
1. **每次只改一个东西**。同时改两个变量，你就不知道是哪个起作用了。
2. **每次改动后记录结果**。写个表格，把实验配置和结果记下来。
3. **不要死磕一个参数**。一个方向调不动了，换个方向试试。
4. **效果下降了就回退**。不是所有改动都会变好，不好就退回去。

**常见误区**：
- ❌ 同时改好几个参数 → 完全不知道哪个有用
- ❌ 一个参数调来调去，死磕到底 → 浪费时间，收益递减
- ❌ 凭感觉调，不记录实验 → 调了半天不知道自己干了啥

---

### 步骤 6：评估与分析

**要做什么**：全面评估模型性能，找出模型的弱点，判断还有没有提升空间。

**为什么要这么做**：
只看一个准确率数字，就像只看考试总分——你不知道哪科学得好、哪科需要补。详细的评估和分析能告诉你"模型哪里不行"，从而指导下一步的改进方向。

**评估清单**：

1. **基础指标**
   - [ ] 测试集准确率是多少？
   - [ ] 和验证集比怎么样？（如果差很多，可能过拟合了）

2. **混淆矩阵**
   - [ ] 画出混淆矩阵
   - [ ] 哪两类最容易混淆？为什么？（长得像？数据少？）
   - [ ] 哪一类准确率最高？哪一类最低？

3. **错例分析**（最重要！）
   - [ ] 把预测错误的图片都拿出来看看
   - [ ] 错误有什么规律？
     - 是图片太模糊？
     - 是标签本身标错了？
     - 是物体太小/位置太偏？
     - 是两类确实长得很像？
   - [ ] 针对这些错误，你能想到什么改进办法？

4. **速度和大小**
   - [ ] 推理一张图需要多久？
   - [ ] 模型文件有多大？

**怎么判断还能不能提升？**

| 现象 | 说明 | 建议 |
|------|------|------|
| 训练准确率远高于验证准确率 | 过拟合 | 加数据增强、加正则化、减少模型容量 |
| 训练准确率也不高 | 欠拟合 | 增大模型、训练更久、调学习率 |
| 某一类特别差 | 类别问题 | 看该类数据是不是太少/质量差 |
| 错例都是"确实很难分清"的 | 模型接近上限了 | 提升空间不大，可以考虑换更好的模型 |
| 错例里有很多标错的标签 | 数据质量问题 | 清洗数据，修正标签 |

---

### 步骤 7：导出与分享

**要做什么**：把训练好的模型导出，写一份项目报告，展示你的成果。

**为什么要这么做**：
- 模型训练好了不算完，能部署、能展示、能让别人看懂，才是一个完整的项目。
- 写报告的过程也是梳理思路的过程——写不出来，说明你可能还没完全理解。
- 以后找实习、找工作，你的项目就是最好的简历。

**导出模型**：
1. 保存 `.keras` 格式：留着以后继续训练或做实验
2. 导出 SavedModel 格式：部署用
3. 转换为 TFLite 格式（带量化）：如果要部署到移动端

**写项目报告**：
报告不用写很长，但结构要清晰。下面有一个模板可以直接填。

**展示成果的小技巧**：
- 放混淆矩阵和错例分析图，比干巴巴的数字有说服力多了
- 放几张样例图 + 预测结果，直观展示模型效果
- 写清楚"我做了什么尝试、分别有什么效果"——这体现了你的实验思维

## 常见陷阱：初学者做项目时常犯的错

### 1. 数据没划分好就开始训练

很多同学下载了数据就直接开始训练，训完了才想起来"哦我还没划分测试集"。这时候再划分，你已经看过数据了，测试集就不"干净"了。

**正确做法**：下载数据后，第一件事就是划分训练/验证/测试集，测试集放着别动，最后再用。

### 2. 一上来就用最复杂的模型

"我直接用最新的大模型，效果肯定好！"——结果代码写了一大堆，bug 也一大堆，调了一周还没跑通。

**正确做法**：从简单的开始，先跑通 baseline，再一步步升级。简单模型跑通了，复杂的才容易上手。

### 3. 只看训练准确率，不看验证准确率

"哇！训练准确率 99% 了！我太厉害了！"——结果一测验证集，只有 70%。典型的过拟合。

**正确做法**：训练过程中始终盯着验证集的表现。验证集才是判断模型好坏的标准。

### 4. 同时改好几个变量

"我把学习率改了，模型结构也换了，还加了数据增强……效果好像变好了？"——但你不知道是哪个改动起作用了。

**正确做法**：每次只改一个变量，其他保持不变。这样你才能知道每个改动的效果。

### 5. 不做数据探索，直接建模型

"数据什么样无所谓，反正神经网络能学。"——结果数据里有一半是损坏的，或者某一类只有 10 张图，模型怎么训都训不好。

**正确做法**：做项目的前 10% 时间用来了解数据。磨刀不误砍柴工。

### 6. 训练几个 epoch 效果不好就放弃

"怎么 loss 还不降？是不是我写错了？"——然后就开始乱改代码，越改越乱。

**正确做法**：先让模型多训一会儿，看看 loss 曲线的整体趋势。深度学习训练本来就需要时间，耐心一点。如果 10 个 epoch 过去了 loss 一点没降，再排查问题。

## 项目报告模板

> 直接复制下面的内容，填空就行。
> 报告不需要写很长，把事情说清楚就好。

---

# 项目名称：[你的项目名称]

## 摘要

用 3-5 句话概括你的项目：
- 做了什么任务？（比如：5 类花朵的图像分类）
- 用了什么方法？（比如：基于 MobileNetV2 的迁移学习）
- 最终效果怎么样？（比如：测试集准确率 92%）

## 一、项目背景与目标

- 为什么选这个题目？
- 要解决什么问题？
- 项目的目标是什么？

## 二、数据介绍

- 数据集名称 / 来源
- 数据规模：多少张图、多少个类别
- 数据样例描述（可以放几张样例图）
- 数据划分方式和比例
- 类别分布情况（平衡 / 不平衡）

## 三、方法

### 3.1 模型结构
- 用了什么模型？（迁移学习的话说明预训练模型）
- 为什么选这个模型？
- 分类头的结构是什么样的？

### 3.2 训练策略
- 优化器、学习率
- 数据增强方式
- 训练的 epoch 数、batch size
- 有没有用回调？（EarlyStopping 等）
- （如果有微调）两阶段训练的配置

## 四、实验结果

### 4.1 基线结果
- baseline 模型的验证准确率
